### 5.2 对每条 action 找真源（不限 site:，全网搜）：

```python
for action in actions:
    real_url = None
    # 优先用 action.card_title 作为核心关键词
    keywords = extract_keywords(action.card_title)  # 至少 3 个
    
    for attempt in range(max_attempts):  # max_attempts = 3
        # 1. web_search：全网搜（不限 site:）
        query = f"{keywords} {today}"  # 不加 site: 限定
        results = web_search(query, top_n=8)
        
        for r in results:
            # 2. 滤 fake-200 关键词
            if is_fake_200(r.url): continue
            # 3. 验证主题词匹配
            if not topic_match(r, action): continue
            # 4. webfetch 验证
            content = webfetch(r.url)
            if not content or "404" in content: continue
            real_url = r.url
            break
        
        if real_url: break
    
    if real_url:
        actions[i].new_url = real_url
        actions[i].status = "replaced"
    else:
        actions[i].status = "partial_skip"
```

13. **SSL `CERTIFICATE_VERIFY_FAILED` 假阴性（2026-10-24 实测 · 已修入 audit 脚本）**：
    `politics.people.com.cn` 报 `[SSL: CERTIFICATE_VERIFY_FAILED] Hostname mismatch, certificate is not

    （就业友好 / 国务院办公厅 / 人工智能）→ **本地网络 TLS 中间人导致的假阴性，不是坏链**。
    **修法**：`_attempt()` 加 `insecure=True`（`ssl.create_default_context()` + `check_hostname=False`
    + `verify_mode=CERT_NONE`）；`check_url()` 里 status 为 None 且 err 含 `CERTIFICATE_VERIFY_FAILED`

14. **HTTP 202 = bot challenge，不是坏链（2026-10-24 实测 · 已修入 audit 脚本）**：
    `www.morningstar.com` 镜像 URL **间歇性**返回 `status=202, size=2444, error=空`。
    探针 9 次：Chrome UA → 200 + 456578 bytes 且正文命中主题；curl / 无 UA → 403；带浏览器 UA 时而 202
    → 典型 bot challenge，**资源真实存在，浏览器能正常打开**。原脚本把非 200 一律归 `fail` → 进 P0
    → 每轮随机炸一次。
    **修法**：
    - 命中 202/204 → 用 Chrome UA 重试 2 次（退避 2s / 4s），拿到 200 即 pass；
    - 仍拿不到 → `category="challenge"` → 进 `warn_urls` 与 **P2**，**不进 P0**（与已有
      `deep_link_challenge` 语义一致）；
    - **判据只用状态码（202/204），不要用 body 特征串** —— 实测真实 200 页面里也含 `captcha` 字样，
      用特征串会误杀正常页。
15. **Python 3.9 的 urllib 不跟 308（已修入 audit 脚本）**：
    `http_error_308` 是 Python 3.11 才加的，本机 Python 3.9.13 → 308 直接抛 HTTPError。
    **修法**：`_attempt()` 手动循环跟随 301/302/303/307/308，
    `nxt = urllib.parse.urljoin(cur, loc)`（Location 常是相对路径，不 urljoin 会 `unknown url type`），最多 5 跳。
    实测 `simedw.com/2026/10/21/world-model-terminal` → 308 → `/…/world-model-terminal/` → 200 + 36226 bytes。
    原脚本把 308 归 `category=redirect`（不算 fail）但**从未校验最终正文** —— 等于漏检。
16. **audit 脚本必须带 `Accept` + `Accept-Language`**：

    `FALLBACK_HEADERS` 都要带。（2026-10-24 已修入）
17. **改脚本三铁律（2026-10-24 再次踩到）**：
    - **行尾**：这些按日期存档的脚本是 **CRLF**，用 LF 写的模式串匹配不到 →
      patch 前先 `src.replace("\r\n","\n")`，写回时按原风格还原。
    - **BOM**：脚本带 **UTF-8 BOM**。`ast.parse(io.open(p, encoding='utf-8').read())` 会报
      `invalid non-printable character U+FEFF`；**用 `encoding='utf-8-sig'` 读**，写回保留 BOM。
      （`python xxx.py` 直接跑没问题，别被预检骗了。）
    - **`Path.write_text` 没有 `newline` 参数**（Python 3.10+ 才有）→ 原子写统一用
      `io.open(tmp, "w", encoding="utf-8", newline="\n")` + `os.replace`。

22. **【新·P0 假阴性 C】`WinError 10053` = 连接层失败（本地代理/TLS 链路），不是 404 —— 新增 `conn_reset` 分类**
    `big5.china.com.cn/txt/2026-10/24/content_118747768.shtml` 报
    `URL Error: [WinError 10053] 你的主机中的软件中止了一个已建立的连接。` → 原脚本归 `fail` → 进 P0。
    探针（4 组 UA + 免校验 + HTTP 降级共 20 次）**全部失败**；curl 报
    `schannel: failed to receive handshake, SSL/TLS connection failed`（0.009s 即挂）。
    **根因**：本机 DNS 是 **Clash fake-IP 模式** —— `Resolve-DnsName big5.china.com.cn` → `198.18.0.120`
    （`198.18.0.0/16` 是 fake-ip 保留段），所有流量走本地代理
    （注册表 `ProxyEnable=1` / `ProxyServer=127.0.0.1:7897`），该站点在代理链上 **TLS 握手被掐断**。
    同域对照：`finance.china.com.cn` → 403（通）、`www.china.com.cn` → 302（通）、`news.china.com.cn` → 000（不通）。
    **修法**：audit 脚本新增 `conn_reset` 分类，连接层错误特征串
    （`10053` / `10054` / `Connection reset` / `Connection aborted` / `Connection refused` /
    `RemoteDisconnected` / `ConnectionResetError` / `Connection timed out` / `连接被中止`）命中即归此类。
    **仍计 P0**（必须处理，不放过），但标签明确指向「先探针再换源」；
    autofix 的 `no_source` 检测同步加入 `conn_reset`（否则该类不会被列进行动清单）。
    **处置顺序**：① 多 UA + 免校验 + HTTP 降级探针 → ② `Resolve-DnsName` 看是否落在 fake-IP 段
    → ③ 换**同源可验证**的等价媒体链接（本次 `big5.china.com.cn` → `www.stdaily.com` 科技日报全文：
    200 + 39361 B + 原标签声称的主题词「输电容量/四成/29万/95%」全命中 + 全篇 120 URL 查重未占用）。
    ⚠️ **不要**因为 TLS 断了就判定「这条事件不存在」—— 本次同一事件有央视网 / 南方电网官网 / 新华社等
    6 家权威源同日发布，可换源而非改写事实。

25. **【新】`curl.exe` 与 Python urllib 的代理行为不一致，探针要跟审计脚本同口径**

26. **【新·P0 假阴性 D】本地代理瞬时 502 / Timeout = 链路抖动，不是坏链 —— 新增 `transient` 重试类**

    `www.cfi.cn/p20261025001431.html`，error 均为 `Timeout`）。

    —— cnyes 首轮 502 → 次轮 200（179724 B，标题「定義下一代決策模型 螞蟻數科推出LingDT-Decision-1.0」）；

    **回归证明**：`2026-10-26/_scratch/verify-transient-class-1026.py` 注入 2 条瞬时错误 →
    `transient_retry_ok=2 / P0=0 / verdict=PASS`，其余 107 条零误伤。
